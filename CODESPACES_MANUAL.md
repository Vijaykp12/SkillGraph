# 🧬 SkillGraph: GitHub Codespaces Development Manual

This manual provides a step-by-step guide to setting up, running, and developing **SkillGraph** entirely in the cloud using **GitHub Codespaces**. This allows you to delete all project code, dependencies, and Docker caches from your local machine.

---

## 🛠️ Step 1: Push Project to GitHub

Before creating a Codespace, ensure your updated project files (especially the new `.devcontainer/` folder and backend/frontend fixes) are pushed to your GitHub repository.

1. Open your terminal on your local machine.
2. Commit and push the changes:
   ```bash
   git add .
   git commit -m "feat: add Codespaces support and devcontainer config"
   git push origin main
   ```

---

## 🚀 Step 2: Create a Codespace

1. Go to your repository on **GitHub.com**.
2. Click the green **Code** button in the top-right.
3. Select the **Codespaces** tab.
4. Click **Create codespace on main**.
5. Wait for the Codespace container to build. GitHub will read our `.devcontainer/devcontainer.json` configuration, set up the workspace, and install the recommended VS Code extensions.

---

## 🔒 Step 3: Configure Port Visibility (CRITICAL)

In GitHub Codespaces, forwarded ports default to **Private** for security. However, because SkillGraph is a full-stack application where the frontend running in your web browser makes direct API and WebSocket calls to the backend, **both frontend (3000) and backend (8000) ports must be set to Public**.

1. In the bottom panel of VS Code in your browser, click the **Ports** tab.
2. Locate Port **3000** (Next.js Frontend). Right-click it, select **Port Visibility**, and set it to **Public**.
3. Locate Port **8000** (FastAPI Backend). Right-click it, select **Port Visibility**, and set it to **Public**.
4. *(Optional)* If you plan to access the Neo4j dashboard visually, set Port **7474** (Neo4j Console) to **Public**.

> [!WARNING]
> If you do not set ports `3000` and `8000` to **Public**, the frontend will fail to communicate with the FastAPI backend, and you will see network connection errors in your browser console.

> [!NOTE]
> **Handling `.gitignore` files in the Cloud:**
> Files like `.env`, database cache, Node/Python dependencies, and ML files (`data/faiss_index.bin`, `data/gnn_model.pt`, etc.) are ignored by git to keep your repository secure and lightweight. 
> Setting up from scratch in Codespaces handles these files as follows:
> - **Virtual environments and dependencies** are clean installed on startup.
> - **`.env`** is created by copying `.env.example`.
> - **FAISS indexes** are generated by the seeding script.
> - **GNN models and mappings** are generated by the training script.

## 🏗️ Step 4: Run the Application

You can run SkillGraph using one of two methods inside your Codespace terminal.

### Method A: Local Hybrid Dev Setup (Recommended)
This runs the databases (Postgres, Neo4j, Redis) inside Docker, but runs Next.js and FastAPI on the host Codespace machine. This is faster and provides hot-reloading and better debugging.

#### 1. Start Database Dependencies
Open a terminal in VS Code and run:
```bash
cd infrastructure/docker
docker compose up postgres redis neo4j -d
```
*(Wait 10-15 seconds for the databases to fully boot up and pass their health checks).*

#### 2. Configure and Run Backend
In the same terminal, go to the backend directory, initialize your environment variables, and build the Python virtual environment:
```bash
cd ../../backend
cp .env.example .env
```
Create a virtual environment and activate it:
```bash
python -m venv venv
source venv/bin/activate
```
Install PyTorch (CPU-only to save memory and avoid GPU package overhead) and other backend dependencies:
```bash
pip install torch==2.4.1 torchvision==0.19.1 torchaudio==2.4.1 --index-url https://download.pytorch.org/whl/cpu
pip install -r requirements.txt
```
Seed the PostgreSQL relational tables, Neo4j skills ontology graph, and build the FAISS index files (e.g. `data/faiss_index.bin`):
```bash
python scripts/seed_data.py
```
Train the Graph Neural Network (GNN) model to generate model weights and mappings (`data/gnn_model.pt`, `data/skill_id_map.pkl`, etc.):
```bash
python app/ai/train.py
```
Start the FastAPI server:
```bash
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

#### 3. Run Frontend
Open a **new terminal split** in VS Code, navigate to the frontend folder, install packages, and start Next.js:
```bash
cd frontend
npm install
npm run dev
```

---

### Method B: Full Docker-Compose Setup
This spins up everything—databases, backend, worker, beat, and frontend—inside Docker containers.

1. Navigate to the docker infrastructure directory:
   ```bash
   cd infrastructure/docker
   ```
2. Build and start all services:
   ```bash
   docker compose up --build
   ```
3. Once running, open a **new terminal tab** and seed the database & generate FAISS indexes:
   ```bash
   docker exec -it skillgraph-backend python scripts/seed_data.py
   ```
4. Train the GNN model inside the container to output GNN weights:
   ```bash
   docker exec -it skillgraph-backend python app/ai/train.py
   ```

---

## 🌐 Step 5: Access the Application

Once your servers are running, GitHub will show a notification popup in the bottom right corner with a link to open the preview. Alternatively:

- **Frontend App**: Open the forwarded URL for port **3000** (e.g. `https://<codespace-id>-3000.app.github.dev`).
- **Backend API Swagger**: Open the forwarded URL for port **8000** with `/docs` appended (e.g. `https://<codespace-id>-8000.app.github.dev/docs`).
- **Neo4j Console**: Open the forwarded URL for port **7474** (Credentials: `neo4j/password`).

## 🧹 Step 6: Cleaning Up Your Local Machine

Now that your project runs entirely in the cloud, you can safely delete the local files and clear caches on your physical machine to free up storage space.

### 1. Delete Local Project Folder
Delete the `SkillGraph` directory from your file system.
- **Windows (PowerShell)**:
  ```powershell
  Remove-Item -Recurse -Force "d:\SkillGraph"
  ```
- **macOS/Linux**:
  ```bash
  rm -rf /path/to/SkillGraph
  ```

### 2. Prune Local Docker Resources
Free up gigabytes of Docker cache, unused images, containers, and volumes:
```bash
docker system prune -a --volumes --force
```

### 3. Clear Local Node/NPM Caches
```bash
npm cache clean --force
```

### 4. Clear Local Python/Pip Cache
```bash
pip cache purge
```
